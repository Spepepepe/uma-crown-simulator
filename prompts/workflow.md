# Uma Crown Simulator - 作業の進め方

このファイルを読んだ AI は、ファイル変更を伴う作業を以下の **作業フロー** に沿って進めてください。

質問への回答・調査だけの依頼（ファイルを変更しないもの）はこのフローの対象外とし、そのまま回答する。

---

## 作業フロー

```
① 作業内容の説明 → ② 方針の提示（ユーザーが選択）→ ②' 作業手順の提示 → 実施 → ③ 作業ドキュメント作成 → ④ コミット
```

### ① 作業内容の説明

着手前に、何をする作業なのかを説明する。

- **目的**: 何のためにやるか
- **現状**: 調査で分かったこと（対象ファイル・現在の設定値・関連する制約など）
- **影響範囲**: 変更が及ぶ箇所（ローカル・CI・本番のどこに効くか）とリスク

### ② 方針の提示

取りうる方針を挙げ、**推奨を 1 つ示したうえでユーザーに選んでもらう**。

- 選択肢ごとにメリット・デメリット・作業量を簡潔に書く
- 推奨には理由を添える
- 選択は `AskUserQuestion` で行い、推奨を先頭に置いてラベル末尾に `(Recommended)` を付ける
- 妥当な方針が 1 つしかない場合はその旨を書き、その方針で進めてよいかを確認する

> ① と ② は 1 つのメッセージにまとめて提示してよい。

### ②' 作業手順の提示

選ばれた方針について、実施する手順を番号付きで示す（1 〜 N）。検証手順（テスト・ビルド・起動確認など）も手順に含める。

```
1. .nvmrc を 26.12.1 に更新
2. backend / frontend の Dockerfile のベースイメージを更新
3. prompts/ のドキュメントを更新
4. Node 26 で lint / 型チェック / テスト / ビルドを実行
5. Docker イメージのビルドと起動確認
```

手順を示したら追加の承認は取らずに実施する。実施中に前提が崩れた場合（想定外の失敗・方針の変更が必要など）は止めてユーザーに相談する。

### ③ 作業ドキュメント作成

実施後、`prompts/worklog.md` のルールに従って作業記録を作成する。

- 結果・判断には検証結果（成功・失敗・未実施とその理由）を事実のまま書く
- スコープ外の課題はバックログに登録する
- 変更が `prompts/` 配下のドキュメントに影響する場合は、ここで合わせて更新する（CLAUDE.md の整合性検証）

### ④ コミット

`prompts/commit.md` のコミットフローに従ってコミットする（プッシュはしない）。コミットしてよいかの確認は選択式（`AskUserQuestion`）で行う。

---

## 報告のしかた

- ①②'の提示、および作業完了時の報告では、変更内容・検証結果・未実施の項目を区別して書く
- 失敗や未確認の事項を省略しない
